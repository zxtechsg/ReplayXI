# Loop 99 — Native texture and UV visual audit

Scope: test/offline QA for the small far-player material change. No playback readback, asset regeneration, downloaded content or user Blender file edits.

`ReplayNativeTextureAudit` reads the texture actually attached to a native material into a bounded floating-point Metal texture. It accepts only opaque uncompressed RGBA8/BGRA8 colour resources, at most 256 pixels per side and 4,096 pixels total. Exported bytes are canonical RGBA, with the real native pixel format, Display P3 gamut, transfer function and explicit top-left origin. It never substitutes the intended palette for the loaded resource.

Six native controls check distinct 2×2 native-P3 colour/row data, all 64 base pixels of a mipmapped one-column strip, a separate sRGB→P3 import against Core Graphics, oversized rejection, rejection of raw/unknown colour semantics and explicit rejection of transparency. Two more check colour-managed native tints and rejection of HDR/translucent tints. All eight pass in `/private/tmp/replayxi-parallel96-101-target-01.xcresult`.

Two test-helper errors were caught before accepting any render. The initial destination omitted the shader-write usage required by RealityKit's copy API. The next destination used linear RGBA8 and mislabeled the native gamut as sRGB: pure source red read back as `[210, 8, 4]`, consistent with linear Display P3. `parallel96-99-postfx-02` passed the production changes but failed both exact byte controls. The helper now uses RGBA32Float to avoid a second low-precision linear quantisation, then re-encodes the native transfer curve. Exact readback fixtures originate in P3; a separate source-gamut conversion test checks Core Graphics within one 8-bit code value. No production texture or admission test was weakened to hide the audit error.

The existing far-floor exporter now also records actual per-vertex UVs and bounded colour textures. Raw/corrected poses must retain the same UVs/texture bytes, geometry, tint and common vertical lift. Textured materials must use UV0 and explicit linear/clamp sampling. No runtime code depends on these diagnostics.

Tint export also needed an explicit colour-space contract. `UIColor.getRed` returned encoded sRGB values, whereas Blender's flat-material input expects scene-linear values. The native exporter now converts `CGColor` to extended linear sRGB and tags the result `Linear Rec.709`. White's observed round-trip value `1.0000001` first triggered the strict offline bound; only conversion roundoff within eight Float32 ULPs at one is canonicalised. HDR values such as `1.01`, negative `−0.01` and translucency are rejected in native controls rather than broadly clamped. The original Loop94 PNGs used the old tint treatment and therefore are not a controlled colour baseline for this change.

The offline validator rejects mismatched UV counts, nonfinite/out-of-range coordinates, unexpected formats/origins, malformed or excessive pixel data and translucent inputs. Ten Python tests pass. Blender receives bottom-up image storage and `V' = 1−V` mesh coordinates, consistently preserving the exported Metal top-left convention. Its installed OCIO configuration has explicit Display P3 and Linear DCI-P3 D65 profiles, used without relabeling them sRGB. Pixel row conversion has its own row/channel test.

Apple's [texture sampling guide](https://developer.apple.com/documentation/metal/creating-and-sampling-textures) documents Metal's top-left texture origin. Its [RealityKit custom-material guide](https://developer.apple.com/documentation/realitykit/modifying-realitykit-rendering-using-custom-materials) distinguishes the extra Y flip for imported USDZ/reality meshes; these far meshes are generated directly. The local XROS SDK confirms the public texture readback and mesh UV APIs used here.

Apple's [texture format colour-space reference](https://developer.apple.com/documentation/realitykit/textureresource/format/colorspace) distinguishes colour primaries from the pixel-format transfer curve. Its [spatial asset session](https://developer.apple.com/videos/play/wwdc2024/10186/) explains the Display P3 gamut used by Vision Pro textures. The [copy API](https://developer.apple.com/documentation/realitykit/textureresource/copy(to:)) requires a shader-write destination. These details are checked separately; the `_srgb` suffix is not treated as proof of sRGB primaries.
